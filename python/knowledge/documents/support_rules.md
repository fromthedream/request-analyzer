# Support Rules

## Categories

Используй одну из следующих категорий для классификации обращения:

* Technical Issue — технические ошибки, сбои и проблемы с работой сервиса.
* Account — регистрация, авторизация, доступ к аккаунту и изменение данных пользователя.
* Payment — оплата, списания, возвраты и другие финансовые вопросы.
* Security — подозрение на взлом, компрометацию аккаунта, утечку данных или другие проблемы безопасности.
* Feature Request — предложения по добавлению или изменению функциональности.
* General Question — общие вопросы, которые не относятся к перечисленным категориям.

## Priority

### High

Используй высокий приоритет, если проблема:

* полностью блокирует использование сервиса;
* связана с потерей доступа к аккаунту;
* связана с финансовыми потерями или ошибочным списанием;
* может указывать на компрометацию аккаунта или утечку данных;
* затрагивает большое количество пользователей.

### Medium

Используй средний приоритет, если:

* основная функциональность работает некорректно;
* проблема существенно мешает пользователю;
* требуется вмешательство сотрудника поддержки;
* проблема не блокирует использование сервиса полностью.

### Low

Используй низкий приоритет, если обращение:

* содержит общий вопрос;
* является предложением новой функциональности;
* касается незначительной проблемы;
* не мешает пользователю продолжать работу с сервисом.

## Recommended Actions

Для обращения выбери одно конкретное действие:

* Technical Issue — проверить технические логи и воспроизвести проблему.
* Account — проверить состояние аккаунта и данные авторизации.
* Payment — проверить информацию о платеже и историю операций.
* Security — проверить события безопасности и состояние аккаунта.
* Feature Request — зарегистрировать предложение и передать его на рассмотрение.
* General Question — предоставить пользователю необходимую информацию.

## Classification Rules

При классификации сначала определи основную проблему обращения.

Если обращение подходит под несколько категорий, выбери категорию, которая наиболее точно описывает основную проблему.

Приоритет определяется серьёзностью последствий проблемы, а не эмоциональностью сообщения пользователя.

Если информации недостаточно для определения высокой или средней критичности, используй более низкий приоритет.

Информация из этой базы знаний является справочной. Не следует придумывать правила, которых нет в контексте.
